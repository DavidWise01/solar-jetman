# NULLRIDER CRUISE — Scalar Zero / K.E.T.

An experimental, no-deployment 3D web page for the user's Solar A ↔ 0 ↔ Solar B preservation model. The page is accessible as an independent GitHub Pages path (assuming Pages for the repository is enabled). The main Solar Jetman homepage, the original dual-solar page, and the frozen NULLRIDER-V0 specification are not modified.

## Run

For the secure-context SHA-256 Web Crypto API, view via GitHub Pages or from a local server:

```bash
cd nullrider-cruise
python -m http.server 8000
# open http://localhost:8000/ in Chrome
```

No server-side service, Railway account, API token, or signing key is needed. The animated graphic attempts to import Three.js v0.164.1 from jsDelivr; when the CDN or WebGL is unavailable it uses a 2D canvas fallback. The preservation checks run independently of graphics.

## Geometry and coordinate rules

- `SCALAR :: 0` is pinned as shared reference.
- Past `−1` pairs with Tach `−2`; present `0` with Gyro `0`; future `+1` with Posi `+3`. Do not normalize Tach/Posi to ±1.
- Solar A is the 0° outbound shell stack `[16,8,4,2×2]`; Solar B is the 180° inbound shell stack `[8,4,2×2]`. Existing reversible pack/unpack logic comes from `dual-solar/engine.mjs`.
- The 208-address dial is **one explicitly chosen representation**: 104 negative and 104 positive shell addresses, plus zero as **reference, not address**. This decomposition is provisional, not an assertion of physical electron shells or a replacement of other KET-208 meanings.
- Shell orientation uses `(+10*n)%360` and `(-10*n)%360`, so n=31 is 310° vs 50°. Angle is a symbolic phase coordinate, not a measured physical orientation of an atom or chip.
- Keep symbolic roll `5/3/1` and fortress inspection `9/7/5/3/1` separate.
- `1/8 × 8 × 1/8` describes concurrent input/lane/output apertures; eight lane bars use a deterministic demonstration made from payload UTF-8 bytes, not measured information flow.
- The attention indicator 12 × 29 × 47 = 16,356 is **derived display geometry**. Its separate 3D page and Q/K/V importer are linked but not duplicated here. No real pretrained Q/K/V has been generated by this demonstration.

## Runtime semantics

A free-running visual cruiser is distinct from the explicit zero-seam preservation test. Editing the payload and selecting a different phase does not launch or reject automatically. Clicking **MEET AT ZERO** snapshots the selected context, SHA-256 hashes the actual UTF-8 bytes, sends them independently through A and B nested reversible packets, then compares both reconstructed byte arrays exactly. Only a preserved pair has one symbolic crossing and `ACCEPT` status. **INJECT FAULT** changes a byte in B and must reject with zero crossings. Every record embeds an explicit, checked cruise-context snapshot.

**Important limitations:** This is a local browser simulation. The data never leaves the browser. Neither a distant host at 0root.ai nor a separate signed receiver is connected. The receipt is **unsigned**; SHA-256 proves byte equality, not ownership or authenticity. A 180° visual rotation is not physical relativistic or quantum time dilation.

## Verify

```bash
node --test engine.test.mjs cruise.test.mjs
python browser_test.py
```

The browser-test harness uses Python hashlib for secure SHA-256 **only in its in-memory test copy**, because the restricted browser cannot navigate to a secure origin. The actual page uses native Web Crypto over GitHub Pages / localhost. The hash logic is also exercised in Node's native Web Crypto implementation.
